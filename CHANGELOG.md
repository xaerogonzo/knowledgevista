# Changelog

## Unreleased

- Libraries, continued. **Each library now remembers its own place** (window size and layout, selection, filters, search, sort, tab; `gui-state.json` is format 2, one entry per library id, and a format-1 file is still read), so going back to a library lands where you left it, and a library opened for the first time starts from the window's last shape. **A launch choice:** with two or more libraries, `kv gui` asks which to open (the last is preselected; a library whose file has gone cannot be chosen; *Don't ask again*, and *File > Ask which library at startup* to turn it back on; `--catalog` and scripted runs never ask). **File > Manage libraries…**: rename, show the catalog in its folder, remove from the list, and **Move catalog…**, which COPIES the catalog (`services/catalog_copy.py`: read-only on the original through SQLite's backup API, verified, renamed into place without overwriting, refused inside the library's own folders, caches copied as a courtesy) and **leaves the original file where it is**; no document is opened or changed, nothing is deleted, and the app's own default library is not movable. 30 planted faults across the new code, all caught; two first runs were weak (a check made trivially true by a file that did not exist, and multi-line patterns that never matched on CRLF files) and were corrected before counting.
- The window can switch libraries: **File > Open library… / New library… / Recent libraries**, and the title names the library shown. `kv gui` with no `--catalog` now opens the library it showed last (falling back to the default if that file is gone). A file that is not a Knowledge Vista catalog is refused read-only and left untouched (opening it for real would have written this program's tables into it), a missing path is never created, and a running job is stopped only after a person says so. Switching replaces the window (`app.Session`) rather than rebinding it, so nothing of one library's jobs or selection can show in another. New: `gui/libraries.py`, `paths.gui_libraries_path()`, `tests/test_gui_libraries.py`, `tests/test_gui_libraries_window.py` (14 planted faults, all caught; one survived at first, which led to a test that the old window saves its state before the new one reads it). A defect the tests found before it shipped: on a machine where the default library had not been created yet the menu marked it "file missing" and offered to forget it.
- Milestone 7: the library window, `kv gui` (the optional `gui` extra; docs/GUI.md). A PySide6 adapter over the same services: the document list with what needs a person first (unresolved, ambiguous, missing, new, then alphabetical) and a *Why* column; a detail pane where every value carries its origin badge (read from the file / returned by a provider / deduced / stated by a person), whether it is locked, and whether its sources agree; **"Why?"** beside each field (how the accepted value came to be, every other proposal with its evidence, rejected ones included, the history); the Review tab (accept, reject, and the batch rule behind a confirmation); search with the coverage caveats; collections, tags, views; Health with *what the library holds* and *what needs attention* as separate texts; **Propose rename** shows the organizer's plan and can save the plan file, and moves nothing (applying stays `kv apply`). The read model is `services/library_view.py`, tested without a display; the window carries no SQL. Work leaves the interface thread in ONE place, `gui/jobs.py`: a write lane of one thread (the catalog's one logical writer), a read lane on read-only snapshots, "latest request wins" channels, cooperative Stop (`extract` and `resolve` gained `should_stop`; a scan stops between files). It follows `catalog_revision`, so `kv tag add` in a terminal appears in the open window. Text from outside is only ever shown as text (`gui/text.py`: plain labels, escaped tooltips, plain messages, and an `audit()` of the live window). `kv open`'s launch logic moved to `services/opener.py` and is shared. In-app driver (`gui/drive.py`, on the template's ledger byte for byte): a script runs inside the process through the real widgets and ends in a verdict; `drive/library_tour.json` is the acceptance run (add folder, scan, extract, resolve, search, evidence, accept, propose rename, open, a separate `kv` process changes the library, restart, state intact), run by `tests/test_gui_drive.py` in a subprocess alongside the scripts that must fail. It refuses to drive the real library unless told, before it creates anything.
  1419 tests (about 250 are the window's, all offscreen; CI sets `KV_REQUIRE_GUI=1` so a missing extra fails instead of skipping). **Rehearsal on a COPY of the real catalog (the folder only read, nothing scanned or changed; 1,841 documents, 1,488 proposals waiting):** the first snapshot 0.2-0.9 s, the window ready in 0.5-0.9 s, a search 0.95 s, a filter 0.06 s, Health 0.8-1.4 s; shots read with real fonts. **91 planted faults** in the window's logic: 12 survived the first suite (a decided proposal counted as waiting; a rejected proposal counted as corroboration; a replaced value reported as a discrepancy; idle announced while a job ran; the audit blind to rich-text widgets; a filter that needed one word, not all; the Why column not sorting into the default order; a locked title not marked; Accept-all-safe enabled with nothing safe; a stale detail shown; shutdown run twice; one mis-aimed mutation); each is now a test and all are caught. **Real defects found on the way:** (1) a dialog's value was read inside the job's lambda, on the worker thread, after the dialog was deleted (a guard test now rejects any widget inside a job function); (2) a worker set its own job's final state, so `wait_idle` could return before the completion callback had run (all state changes now happen on the interface thread); (3) pressing Stop gave no feedback until the job noticed; (4) `QSortFilterProxyModel.invalidateFilter` is deprecated in PySide6 6.11 and the driver's ledger records warnings; (5) found by the rehearsal, in milestone 3: a DOI in a PDF's metadata with a trailing U+201A (a comma look-alike) was a second, different proposal beside the right one, so the window showed the correct DOI as DIFFERS; `normalise_doi` now trims typographic trailing punctuation too (`, " ' and their typographic forms).
  Not in the window, on purpose (docs/design-notes.md): applying a plan, deleting anything, an online-lookup button, the reader (milestone 8: the window hands a file to your PDF viewer and says which page to go to).
- Milestone 6: the reversible organizer (docs/ORGANIZER.md). `kv plan create` proposes renames (and, with `--layout by_year`, moves) from ACCEPTED titles only, under a versioned, deterministic naming policy (`naming-1`: NFC, no characters or reserved names Windows forbids, a stable hash on a cut name, collisions resolved by artifact id never by directory order), as a frozen plan file with its own hash, written outside the library and registered with the catalog that made it. Nothing moves until `kv apply <plan>`, which refuses a plan the library no longer matches (judged per item, so an unrelated tag does not matter), re-hashes every source, refuses to overwrite or to move through a symlink or junction, skips a locked file with a warning rather than failing the batch, journals each move BEFORE touching the file and commits the outcome with the catalog's location update in one transaction, orders chains and stages cycles through a journaled temporary name. `kv undo` takes an apply back and refuses any file edited since; `kv recover` reconciles an interrupted operation with the disk and never retries; `kv history`, `kv root allow-organize` (per root, off by default) and a `doctor` category `operations` complete it. `apply`, `undo` and `recover` are the only commands of kind `filesystem` in `kv capabilities`. Never deletes.
  **Rehearsal on a COPY of the real library (2026-10-07; nothing was run on a real folder):** 1,862 files copied (118 s), the scratch catalog repointed at the copy. `plan create` 4.1 s: 364 renames (every document with an accepted title), 1,498 left alone (no accepted title). `apply --dry-run` 17 s; `apply` 8.6 s, 364 succeeded, 0 problems; a `kv scan` afterwards hashed 0 files and found 0 new, moved or missing; `doctor` clean; `undo` 14 s, 364 undone; **the tree (every file's bytes and every folder) was byte-identical to before.** The Windows matrix is in tests/test_organizer_apply.py (long and extended paths, reserved and hostile names, case-only and Unicode-form renames, read-only and hidden files, junctions and symlinks, locked files, an antivirus race, chains, swaps, rings, stale and edited plans, interruption, an uncertain item, a changed source, a destination that appeared, repeated apply, undo after an edit); UNC roots are tested as path composition only.
  100 planted faults: 26 survived the first suite; they led to one real defect (undo applied the destination-naming rules to the name a file is put back under, so a file another program had called ` lead.pdf` could be renamed and never restored) and to tests/test_organizer_edges.py; 2 equivalent mutations remain (a containment check made redundant by the link and name checks, and a filter on retired documents, which hold no artifacts).
- Milestone 5: the integration surface. `kv capabilities` (needs no catalog) reports the four version numbers separately (`protocol_version`, the JSON envelope, the catalog schema, the MCP revisions), every command flagged read-only or not, and the MCP tools; a test holds that table equal to the parser and the contract. `kv locate` answers "where is this NOW" from a document id, a SHA-256 or prefix, a name or a `knowledgevista://` reference, `stat`s every path (the disk beats the catalog), resolves an id a merge retired to its survivor and says so, and never guesses. `knowledgevista://document|artifact/<id>[/page/N|/label/L]` is a strict, one-spelling grammar. `kv open` hands a file to the OS viewer (the page is reported, not navigated to). Listings carry opaque cursors that go `KV_CURSOR_STALE` after any catalog change or reordering instead of skipping or repeating; `--limit` is 1 to 1000 and refused, not clamped. `kv mcp` serves nine read-only tools (search, document, page by position or by printed label, resolve, metadata, related, duplicates, locate) over stdio with no dependency; the catalog is opened `mode=ro` and never migrated, page text is returned as untrusted data, and a test requires every tool to leave the catalog and extraction store byte-identical. 79 planted faults in the new code: 8 survived the first suite and were closed by tests (three of the 8 were guards made redundant by a later check, kept because they give the error its right words, and now pinned by it). See docs/INTEGRATION.md and docs/MCP.md.
- Milestone 4: relations and virtual organisation. `kv relate` looks across the library for the same publication twice (identical extracted text under different bytes, a shared accepted DOI, the same title and first author), supplements, corrections, chapters of a book, preprint/published pairs and replaced files, and PROPOSES each with its evidence; nothing is related or merged by a run, and a rerun with nothing new changes nothing. `kv relations list/accept/reject/add/remove` is the queue; accepting a `same_document` proposal merges two documents (the absorbed one is retired, never deleted; every artifact id is kept; relations, collections, tags, open proposals and accepted values the survivor lacks come along) and `kv document split` takes an artifact back out, reviving a merged-away document under its original id, even after a chain of merges. `kv dupes` keeps the four levels of duplicate apart. Collections, tags, saved searches (stored as a parsed query with its language version) and computed system views (`kv view`) touch no file. Search language 2 adds the filters `author: year: doi: kind: tag: collection:`, which read accepted metadata only. `doctor` gains a `relationships` category. Two defects only real data showed were fixed: old Wiley DOIs containing `<`/`>` were corrupted by markup stripping, and a merge left the open proposals about the absorbed document stale. 89 planted faults in the relation, organisation and filter code were run against the suite: 27 survived the first suite and were each closed by a test (tests/test_relations_edges.py); the 4 that still survive are equivalent (a guard made redundant by the check after it, an anchored regex's slice, and a revival condition no sequence of merges can reach). See docs/RELATIONS.md.
- Milestone 3: metadata. `kv resolve` proposes DOIs, titles, authors, ISBNs and arXiv ids from each document's text, Info/XMP and first-page layout, as
  *proposals with their evidence*; a printed DOI is classified own / foreign / ambiguous from several features (position is one of them), and a DOI that
  three or more documents each print as their own is recognised as a parent work (a book's), not any one document's. `--online` asks Crossref (a DOI or a
  title is all that is sent; off until `kv config set online_lookup true`; `--list-requests` shows exactly what would be sent), compares the record with the
  PDF, and a record that does not match proposes nothing. `kv review list/accept/reject` is the queue; `kv resolve --accept-safe` applies one named,
  recorded rule (`safe_batch_v1`) to proposals that earned `safe`; `kv metadata set/clear/lock/unlock` states a value by hand. Rerunning changes
  nothing; a provider outage changes no accepted value and the run resumes from a cache of definite answers. `explain`, `stats` and `doctor` cover
  metadata, and every PDF is either titled or in a stated state. See docs/METADATA.md.
- The plan's 66% DOI-coverage target is restated: it came from a figure that counted one encyclopedia's DOI as each of its 160 entries' (docs/ARCHITECTURE.md). A full online run over the real 727-PDF library accepted 393 correct DOIs (54%; 69% of the PDFs that are not entries of that encyclopedia) and 360 titles, and found, after the 80-document sample had passed, a matcher hole (a book record with no authors and a file with no layout title could be `exact`), a ligature inside an accepted DOI, and a letter-spaced scan accepted as a title; all fixed and tested (docs/METADATA.md).
- `kv extract`'s worker gained a `front` request (Info, XMP and first-page layout) used only by `resolve`.

- Milestone 2: text extraction and search. `kv extract` reads PDF text in a separate, killable worker process
  (a Windows Job Object caps its memory and kills it with the parent; each page that hangs or crashes the worker is
  recorded as failed and extraction resumes at the next page), into a rebuildable extraction store in the cache keyed by
  artifact hash. `kv search` (phrase, `*` prefix, `|` alternatives, `--near`, `--also`) always states its coverage;
  searching nothing searchable is an error, not an empty success. `kv show` addresses a page by `--pdf-page` (position)
  or `--label` (printed label), never an ambiguous "page". `kv import openchem-index` reuses an OpenChem index as
  provisional text, accepted only for hashes the catalog already holds. Profile versioning marks extractions stale when
  the extractor changes. doctor and stats cover extraction and search. See docs/SEARCH.md.
- Design correction: extraction lives in a cache SQLite file, not catalog tables, so deleting it provably loses no
  catalog state (docs/ARCHITECTURE.md).

- Milestone 1: the identity substrate. Roots, locations (history, never deleted), artifacts (SHA-256) and documents;
  a scanner that reconciles disk with the catalog (moves and renames keep identity, replaced bytes become a new
  artifact and document, absence is `missing` and never a deletion, an unavailable or half-mounted root changes
  nothing, a killed scan is recoverable); `kv root add/list`, `scan`, `stats`, `explain`, `doctor`, `verify`; a stable
  JSON envelope with documented exit codes and error codes (docs/CLI_CONTRACT.md). 241 tests; 36 planted faults in
  the scanner and services were each caught.
- Deviation recorded: artifact state is not a stored column (see docs/ARCHITECTURE.md).
- A root that contains the catalog file is refused; Access `.mdb` files are recognised as databases (found by
  running against a real 1,862-file library).

- Milestone 0: repository bootstrap. Package skeleton, `kv --version`, a single `paths` module for app-data
  locations, a forward-only migration framework (atomic per migration, backup with SQLite's backup API, refuses a
  newer schema), a generated-fixture PDF builder, a safe-repo check, a lockfile-closure licence inventory, and the
  invariants, safety model and architecture documents.
